# PLANS.md

Use this ExecPlan template for every feature plan. A feature plan must be self-contained enough that a fresh Codex session can continue from `AGENTS.md` plus that plan without rereading the whole repository.

## Purpose

Describe the user-visible goal and why it matters.

## Current Understanding

Summarize verified facts, relevant files, existing behavior, and constraints. Mark uncertainty clearly.

## Open Questions

List unresolved product, technical, UX, compatibility, and validation questions. Include answers when resolved.

## Proposed Design

Describe the chosen approach. Name expected files, classes, methods, data flow, UI flow, and compatibility behavior.

## Implementation Steps

1. Small, ordered step.
2. Small, ordered step.
3. Small, ordered step.

## Validation

List targeted builds, tests, manual checks, fixtures, and expected outcomes. If a command is inferred or cannot be run, say so.

## Progress

Track completed steps with dates/session notes.

## Surprises and Discoveries

Record facts learned during implementation that affect scope, design, tests, or future work.

## Decision Log

Record decisions with reason and date. Link ADRs when useful.

## Handoff Notes

Explain current state, changed files, remaining work, validation run, validation not run, and exact next step.
